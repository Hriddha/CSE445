This notebook evaluates Decision Tree and XGBoost classifiers on the UCI
**Car Evaluation** dataset (1,728 instances, 6 categorical attributes, 4
target classes: `unacc`, `acc`, `good`, `vgood`). Per the assignment
specification, the data is split *sequentially* — the first 70% for
training, the next 15% for validation, and the last 15% for testing — with
hyperparameters selected using the validation set only. All evaluation
metrics (Accuracy, Confusion Matrix, macro-averaged Precision, Recall, and
F-score) are implemented manually with NumPy; no evaluation-metric library
function is used anywhere. A key empirical finding of this study is that,
because the raw Car Evaluation data is laid out as a systematic, exhaustive
enumeration of attribute combinations rather than a randomly ordered sample,
a strictly sequential split produces training, validation, and test subsets
with very different class compositions — the training set contains almost
no `good` or `vgood` examples — which materially limits what *any*
hyperparameter configuration of either model can achieve on the minority
classes. This is documented below as part of the hyperparameter-tuning
experimentation log, alongside the standard grid/random search results for
both models.



## Introduction

Multiclass classification requires a model to assign each instance to one
of several mutually exclusive categories, and a good evaluation must look
beyond overall accuracy to how well each class individually is served,
which motivates reporting macro-averaged Precision, Recall, and F-score
alongside the confusion matrix. The Car Evaluation dataset is a well known
benchmark for this purpose: it maps six ordinal, categorical attributes of
a car (purchase price, maintenance cost, number of doors, passenger
capacity, luggage boot size, and estimated safety) to an overall
acceptability judgement. This notebook trains and tunes a Decision Tree
Classifier and an XGBoost Classifier on this task, selecting hyperparameters
using a held-out validation set and reporting final performance on a
held-out test set, all under a strictly sequential (non-shuffled) split as
specified by the assignment.

Unlike in the earlier regression and binary-classification notebooks,
XGBoost's random-search validation accuracy here does **not** clearly
exceed the Decision Tree's grid-search validation accuracy — both hover in
a similar range, and, as shown in the final comparison table below, the
Decision Tree slightly edges out XGBoost on the test set. This runs counter
to the usual expectation that a gradient-boosted ensemble outperforms a
single tree, and is discussed further below: it is consistent with the
same training-set class-scarcity problem identified in Experimental
Observation #1 — with only a handful of `good`/`vgood` training examples,
there is not enough minority-class signal for boosting's iterative
error-correction to exploit, so it gains little over a single regularized
tree.

## Discussion

**Overall performance.** On the test set, the Decision Tree achieves higher
accuracy than XGBoost (67.69% vs. 60.00%) and a higher macro-averaged
F-score (0.362 vs. 0.278). This is a notable reversal of the pattern seen
in the earlier regression and binary-classification notebooks, where
XGBoost consistently outperformed a single Decision Tree. The following
observations, drawn directly from the confusion matrices and the
experimentation log above, explain why.

**Both models fail completely on the two minority classes.** Neither model
correctly predicts a single `good` or `vgood` test instance — the Decision
Tree's test confusion matrix shows all 46 `good` and all 34 `vgood` test
cars predicted as `acc`, while XGBoost predicts the same 80 cars as a mix
of `unacc`/`acc`. This is a direct consequence of Experimental Observation
#1: the sequential 70/15/15 split, applied to a dataset that is a
systematic (non-random) enumeration of attribute combinations, leaves only
**3** `good` and **14** `vgood` examples in the training set out of 1,209
rows. The trial-and-error experiment with deeper trees (Trial 3, Decision
Tree section) confirmed this is not a fixable hyperparameter problem: even
a fully unconstrained tree that memorizes 100% of the training set (train
accuracy 1.0) still predicts zero `good`/`vgood` cars correctly on the test
set, because it never saw enough of them to learn the relevant decision
boundaries in the first place.

**Why the Decision Tree edges out XGBoost here.** The two models fail on
the minority classes similarly, but differ sharply on the majority classes.
The Decision Tree reaches perfect recall on `acc` (36/36 correctly
identified) by aggressively routing borderline cases into the `acc`
bucket — at the cost of precision (only 36 of the 120 cars it labels `acc`
actually are `acc`; the rest are `good`/`vgood` cars it cannot
distinguish). XGBoost is more conservative: it achieves higher precision on
`unacc` (85.7% vs. the Decision Tree's 100% — both are strong) but only
33.3% recall on `acc` (12/36), leaving more `acc` cars misclassified as
`unacc`. With a training set this thin on two of the four classes, XGBoost's
iterative boosting has too little minority-class signal to exploit, so it
gains nothing over — and here slightly underperforms — a single, heavily
regularized tree. This is consistent with the standard explanation for when
ensembling helps: boosting reduces variance when there is enough data and
non-linear signal for successive trees to correct each other's errors; that
condition is not met for the `good`/`vgood` classes in this split.

**Effect of hyperparameter tuning.** Tuning improved the Decision Tree from
a baseline validation accuracy of 71.43% to 75.68% (+4.25 points), and
XGBoost from 68.73% to 69.11% (+0.38 points) — a much smaller gain for
XGBoost, again pointing to the training-data scarcity as the binding
constraint rather than hyperparameter choice.

**Precision vs. Recall trade-off summary (test set, macro-averaged):**

| Model | Accuracy | Avg. Precision | Avg. Recall | Avg. F-score |
|---|---|---|---|---|
| Decision Tree | 0.6769 | 0.3250 | 0.4931 | 0.3619 |
| XGBoost | 0.6000 | 0.2469 | 0.3333 | 0.2776 |

The Decision Tree's advantage is driven entirely by Recall (0.493 vs.
0.333) — its willingness to over-predict `acc` catches more of the
minority-class cars than XGBoost's more conservative predictions, even
though neither model correctly labels them.

## Conclusion

This notebook applied a Decision Tree Classifier and an XGBoost Classifier
to multiclass prediction of car acceptability, using a strictly sequential
70/15/15 train/validation/test split, validation-only hyperparameter
selection, and fully manual implementations of Accuracy, Confusion Matrix,
and macro-averaged Precision/Recall/F-score (no evaluation-metric library
was used). On the test set, the Decision Tree (max_depth=3,
min_samples_split=2, min_samples_leaf=1, criterion=gini) outperformed the
tuned XGBoost model (max_depth=5, learning_rate=0.1, n_estimators=300,
subsample=0.8, colsample_bytree=1.0, min_child_weight=1, gamma=0) on every
metric — Accuracy (0.677 vs. 0.600), Avg. Precision (0.325 vs. 0.247), Avg.
Recall (0.493 vs. 0.333), and Avg. F-score (0.362 vs. 0.278) — reversing the
pattern from the earlier regression and binary-classification experiments.

The trial-and-error experimentation log identified the root cause: the raw
Car Evaluation dataset is ordered as a systematic enumeration of attribute
combinations rather than randomly, so the mandated sequential split leaves
the training set with only 3 `good` and 14 `vgood` examples out of 1,209
rows. This was confirmed to be a data-coverage problem rather than a
hyperparameter problem — even a fully unconstrained, memorizing Decision
Tree (100% training accuracy) still could not correctly classify a single
`good` or `vgood` car in the test set. Under this constraint, XGBoost's
usual advantage from iterative boosting has too little minority-class
signal to exploit, and a single, shallow, heavily regularized tree
generalizes at least as well.

**Practical implication.** For datasets that are not randomly ordered — as
is the case here — a strictly sequential split, while satisfying the letter
of a "no shuffling" requirement, can produce training data that is not
representative of the full label distribution. Where the assignment
specification allows it, a stratified or randomly-shuffled split (still
using a fixed seed for reproducibility) would likely let both models,
particularly XGBoost, learn the minority classes and yield a fairer
comparison; this is noted here as a methodological limitation of the
mandated split for this specific dataset, not of the modelling approach
itself.
